# Competitive Positioning Brief

## Overview

建立公平、可追溯且能直接支持 Marketing decision 的 Competitive Brief。先分別建立我方與競爭者 dossier，再比較 Positioning、Audience、Message、Proof、Offer、Channel 與 Content；不先決定輸贏再挑證據。內部 field signal、公開事實、分析推論與未知保持分離。

## When to Use

- 比較具名競爭者、替代方案、Build／Buy／Do nothing。
- 建立 Category positioning、Messaging whitespace 或 Campaign differentiation。
- 準備 Product launch、Competitive response、Battlecard 或 objection package。
- 比較競爭者公開內容、Claims、Customer proof、Channel presence 與 recent moves。
- 找出我們尚未覆蓋的 Audience question、Content topic 或 Proof gap。

## When NOT to Use

- 單一 Account 的 Deal strategy 或 Sales outreach。
- 取得未公開資料、冒充身份、繞過 paywall／權限或接觸競爭者員工。
- 只做 SEO technical audit → `seo-content-optimization`
- 沒有比較 anchor 的百科式公司介紹。
- 將傳聞、社群留言或 field opinion 當成產品事實。

## Quick Start

1. 確認 Seller／Brand、競爭者或 category、Audience、region、time point 與決策用途。
2. 用 `ask` 尋找內部 approved positioning、battlecard、campaign learning、customer evidence 與 prior comparisons。
3. 對 current public facts 查直接來源，記錄版本、方案層級、地區、發布日期與觀察日期。
4. 分別建立 dossiers，完成 Evidence symmetry check 後才產生 comparison matrix。
5. 交付 Positioning implications、Message whitespace、What to say、What not to claim、Validation questions 與 sources。

## Core Instructions

### 1. Resolve the comparison anchor

至少需要：

- 我方 Brand／Product／Offer 或明確 Category baseline。
- 具名 competitor(s)、替代方案或使用者允許發現的有限 candidate set。
- Audience／Segment、Region、use case 與 buying stage。
- 決策：Campaign、Launch、Website、Content、PR 或 Executive briefing。
- 比較時點與方案層級。

如果名稱可能是 Customer、Partner 或 Competitor，使用內部 evidence 解析後再比較。自動發現競爭者時最多提出五個候選並說明依據，不進行無邊界 landscape crawl。

### 2. Gather evidence in authority order

1. 使用者提供的 approved materials、briefs、research 與 source pack。
2. M365 中的 approved positioning、product docs、Brand／Claim library、customer evidence。
3. 我方與競爭者官方 product、pricing、launch、customer story、security、investor 或 regulatory sources。
4. 可信 secondary research，用於特定缺口。
5. Internal field signal，僅作方向性資訊並標示來源類型。

對 Product capability、Price、Availability、Partnership、Certification、Customer count、Performance 或 Roadmap 的主張，需 current direct source。Pricing 需對齊 currency、billing term、region、tier、minimum 與觀察日期；無法對齊時標示不可直接比較。

### 3. Build dossiers before the matrix

每個組織先獨立建立：

- Stated positioning 與 category language。
- Target audience／segment 與主要 use cases。
- Core message、supporting claims 與 CTA。
- Proof：customer stories、numbers、certifications、third-party validation。
- Offer／packaging／public pricing logic。
- Content themes、channel／format presence 與 recent launches。
- Explicit limitations、unknowns 與 source dates。

這能避免只對競爭者做嚴格查證、卻以內部印象描述我方。若我方 claim 也無核准來源，同樣標示 `未驗證`。

### 4. Compare with evidence symmetry

只比較資料定義、層級與時點足夠對稱的維度。建議維度：

- Audience fit 與 Problem framing。
- Value proposition 與 message clarity。
- Differentiated capability，但不把 feature count 當價值。
- Proof quality 與 Customer relevance。
- Adoption、Integration、Security、Privacy、Governance 前提。
- Offer／commercial model 與可見 friction。
- Content coverage、format、funnel stage 與 question ownership。
- Brand tone、category language 與 trust signals。

資料不對稱時填 `Evidence insufficient`，不要宣告 winner。Comparison 需保留 competitor strength；公平描述對手能提高 brief 的可信度。

### 5. Identify positioning and content whitespace

Whitespace 必須同時滿足：

1. Audience 有證據顯示在意該問題或結果。
2. 我方有核准且可證明的能力／觀點。
3. 競爭者尚未清楚佔據，或其 proof／message 有可驗證缺口。
4. 有適合的 channel、content format 與 next test。

只有競爭者沒提到、但 Audience 也不在意的主題，不是有效 whitespace。

### 6. Create the positioning response

依序產出：

- Category frame：用 Audience problem 描述，不以貶低對手開場。
- Core difference：一項有 evidence 的差異化結果。
- Proof：可公開且與 Segment 相符的證據。
- Qualification：適用條件與限制。
- Discovery／validation question：用來確認 Audience 是否在意。
- Counter-message：回應競爭者優勢，不使用 FUD。

### 7. Build a Marketing battlecard when requested

Battlecard 包含：

1. Audience decision criteria。
2. Competitor position、strength、limitation 與 proof。
3. 我方 evidence-backed differentiation。
4. Message pillars 與 supporting proof。
5. Objection／response／validation question。
6. Content／channel opportunity。
7. What not to claim。
8. Direct sources and dates。

## Output Format

```markdown
# Competitive Positioning Brief

## Scope and decision
## Executive findings
## Evidence dossiers

## Comparison matrix
| Dimension | Our position / evidence | Competitor position / evidence | Marketing implication | Confidence |
|---|---|---|---|---|

## Positioning and messaging whitespace
| Audience need | Available proof | Competitive gap | Proposed message | Validation |
|---|---|---|---|---|

## Response guidance
- What to emphasize
- What to acknowledge
- What not to claim

## Content opportunities
## Unknowns and contradictions
## Sources with publication dates
```

## Work IQ Tool Rules

- `ask`：探索 approved positioning、campaign learning、battlecards、meeting evidence 與 product files。
- `search_paths`、`get_schema`、`fetch`：驗證內部來源版本、metadata、claim 與 approval。
- `fetch_blob`：讀取特定 deck、document 或 source pack。
- 不建立或修改 Brand／Campaign artifact，不向外發布或聯繫競爭者。

## Examples

**User:**「比較我們和 Competitor X 的 AI governance 定位，準備 Product Launch。」

**Correct behavior:** 對齊 Audience、region、product tier 與觀察日期，分開建立雙方 dossier，再比較 Positioning、Proof、Adoption 與 Content gap；將未公開 Roadmap 保持未知。

## Guardrails

- 不使用 deception、非公開資料、洩漏文件、個人資料或未授權競爭情報。
- 不捏造價格、Roadmap、Customer、Certification、Performance 或 market share。
- 不使用無來源 superlative、FUD、貶低語言或假的 comparison winner。
- 不把競爭者弱點直接等同我方優勢；我方仍需有 proof。
- 不把 Public news 當成具名 Customer 的 intent 或 objection。

## Common Issues

| Issue | Cause | Fix |
|---|---|---|
| Matrix 每列我方都贏 | 先有結論再選證據 | 重建獨立 dossiers 並做 symmetry check。 |
| 價格無法比較 | Tier／region／term 不同 | 標示不可直接比較並列條件。 |
| Whitespace 太多 | 只看競爭者沒寫什麼 | 加入 Audience need 與我方 proof gate。 |
| Battlecard 變攻擊稿 | 使用無來源 FUD | 改為 decision criteria、evidence 與 question。 |
| Current facts 過期 | 未記錄觀察日期 | 重新驗證官方來源與發布日期。 |
