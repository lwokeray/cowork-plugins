# Content Strategy and Editorial Calendar

## Overview

把內容需求整理為能回答 Audience 問題、支持 Journey 並產生可衡量結果的 Content system。Calendar 是策略的執行視圖，不是內容策略本身；每一項內容都要有 Audience、Question、Message、Proof、Format、Distribution、CTA、Owner、Dependency、Review 與 Success signal。

## When to Use

- 建立年度／季度／Campaign Content strategy 與 Editorial calendar。
- 盤點既有內容、重複、過期、Proof gap 與 Journey gap。
- 設計 Pillar／cluster、Thought leadership、Customer proof、Education 與 Conversion content。
- 建立一份核心內容到多 Channel 的 repurposing plan。
- 規劃 Localization、Accessibility、Brand／Legal review 與 content lifecycle。

## When NOT to Use

- 直接撰寫 Blog、Landing page、Case study 或 Video script → `marketing-content-creation`
- 將一篇內容改成不同渠道版本 → `channel-content-adaptation`
- 完整 Campaign strategy → `campaign-strategy-plan`
- SEO technical diagnosis → `seo-content-optimization`
- 建立 Planner task 或直接發布 → `marketing-work-management`

## Quick Start

1. 確認期間、Campaign／Business objective、Audience、Journey、Channels、capacity 與現有 content repository。
2. 用 `ask` 建立內容 inventory、Brand／Claim source、Customer questions、Campaign learnings 與 performance signals。
3. 用 `fetch`／`fetch_blob` 驗證 canonical asset、version、date、owner、status、proof 與 performance source。
4. 建立 Content pillars、journey coverage、topic/format map、repurposing map 與 editorial sequence。
5. 交付 Calendar、Brief-ready rows、dependencies、governance、measurement 與 deprecation actions；不建立或發布內容。

## Core Instructions

### 1. Resolve strategy scope

先決定：Period、Audience／Region／Language、Business or Campaign objective、Journey stages、included channels、production capacity、fixed dates、content owners、approval roles 與 measurement cadence。若 scope 含多產品或地區，先建立 shared core 與 local variant，不把所有內容混成單一 Calendar。

### 2. Build a verified content inventory

使用最小足夠欄位：Asset title、URL／ID、Type、Audience、Journey stage、Topic、Message、Proof、Owner、Status、Version、Publish date、Review／expiry date、Language、Channel、Performance source。

以 `ask` 找 candidate，再用精確讀取去重。相同檔名不一定是同一資產；以 canonical URL／ID、version、content hash-like evidence 或 approved owner 判斷。檔名含 `final` 不代表 canonical。

將資產分類：`Keep`、`Refresh`、`Repurpose`、`Consolidate`、`Retire`、`Unknown`。Retire 是建議，不在本 Skill 直接刪除或取消發布。

### 3. Map audience questions to the journey

建立 Content opportunity matrix：

| Audience / stage | Question or job | Current evidence | Existing content | Gap | Desired next action |
|---|---|---|---|---|---|

Awareness 內容回答「為何現在值得注意」；Consideration 回答「有哪些選擇、需要什麼 proof」；Decision 回答「風險、實施、成本、適用條件」；Adoption／Retention 回答「如何取得價值、處理障礙」；Advocacy 回答「如何分享、推薦或共創」。不要只在 Awareness 大量堆內容。

### 4. Define content pillars

每個 Pillar 至少包含：Audience need、Point of view、approved message、Proof sources、topics in／out、priority journey stages、primary formats、distribution role、CTA、owner、success metric 與 review date。

Pillar 應彼此可辨識並可延續，不以單一產品 feature 或一次性 Campaign slogan 命名。最多五至七個；過多時合併到更高層 Audience question。

### 5. Design topic and format architecture

對每個 priority topic 選擇最合適的 format，而不是所有 topic 都寫 Blog：

- Point of view／category education：Article、brief、webinar、executive deck。
- Proof／consideration：Case study、demo narrative、comparison、FAQ。
- Instruction／adoption：Guide、checklist、video、template。
- Conversion：Landing page、email、event page、interactive asset。
- Social discovery：short post、carousel brief、short video script、quote／data visual。

Format 選擇需考慮 Audience consumption、production capacity、proof availability、accessibility、localization 與 distribution channel。

### 6. Create repurposing logic

一份 Hero asset 可以衍生多項內容，但每個 derivative 必須：

- 保持核心 Claim 與 source fidelity。
- 為 Channel／Audience 重新構圖，而非截短原文。
- 有獨立 CTA 與 success signal。
- 保留 source asset、version、approval 與 expiry inheritance。
- 不讓同一 Audience 在短期內收到高度重複訊息。

建立 Source → Derivative → Channel → Publish sequence → Owner → Review 的 map。

### 7. Build an executable editorial calendar

Calendar row 必須有：Date／Window、Asset、Purpose、Audience、Journey、Pillar、Format、Channel、Core message、Proof、CTA、Owner、Dependencies、Reviewers、Localization、Status、Measurement。

從 fixed milestone 倒排 Research、Brief、Draft、SME／Customer approval、Brand／Legal review、Design、Localization、Accessibility QA、Publish／handoff 與 Measurement checkpoint。不要在 Calendar 中自動標示 Approved 或 Published。

### 8. Balance cadence and capacity

先依 Team capacity 估算可完成的 asset points 或 production hours，再安排 cadence。保留 reactive capacity，但不能使用固定比例冒充公司規則。檢查：Audience fatigue、Channel duplication、review bottleneck、SME availability、seasonality、regional holiday、product availability 與 Campaign collision。

### 9. Define content measurement

每項內容選一個主要 success signal，對應其 Journey role：Qualified reach、engaged consumption、CTA completion、event progression、assisted conversion、adoption action 或 reuse efficiency。不要用 Pageviews 評估所有內容。

保留 KPI formula、source、window、baseline、target／learning threshold、attribution limits 與 review owner。低流量內容可用 qualitative signal 與 leading indicator，但不得宣稱 ROI。

### 10. Govern the lifecycle

對每項 asset 建立 Review／expiry rule：Price、product capability、security、law、customer result、event date 或 current-year title 可能需要短週期 review。過期內容標 `Review required`，不自動刪除。Customer quote、logo、claim 與 legal disclaimer 的 approval expiry 各自管理。

```markdown

## Content pillars
## Topic and format architecture
## Repurposing map
## Editorial calendar
| Publish window | Asset | Audience / stage | Pillar | Message / proof | Channel | CTA | Owner | Dependencies / reviews | Status | Measure |
## Lifecycle and governance
## Gaps, risks, and decisions
```

## Work IQ Tool Rules

- `ask`：發現 content inventory、Brand、Campaign、Customer questions、meetings 與 performance context。
- `search_paths`、`get_schema`、`fetch`：驗證 files、list、workbook、task 與 metadata。
- `fetch_blob`：讀取指定 canonical asset 內容。
- 保持 Read-only；建立 Task／register 交給 `marketing-work-management`，內容撰寫交給 `marketing-content-creation`。

## Examples

**User:**「規劃下季 B2B AI 內容日曆。」

**Correct behavior:** 先盤點現有內容與 Audience questions，建立 Pillars／Journey gaps／format mix／repurposing／capacity-aware calendar；不直接排出每天一篇沒有 proof 與目的的社群貼文。

## Guardrails

- 不捏造 Customer question、Search demand、performance、Owner、Publish date 或 approval。
- 不把 volume 等同 strategy，不用固定 cadence 當 universal best practice。
- 不自動刪除、發布、排程、建立 Task 或更新正式 Calendar。
- 不重複使用過期 claim、customer quote 或 event CTA。
- 不因可用 AI 生成內容就忽略 SME、Brand、Legal、Localization 與 Accessibility review。

## Common Issues

| Issue | Cause | Fix |
|---|---|---|
| Calendar 很滿但無策略 | 沒有 Audience question／Journey | 先建立 opportunity matrix。 |
| 每篇都是 Blog | Format 由習慣決定 | 依任務、proof、channel 與 capacity 選擇。 |
| 重複內容很多 | 未做 canonical inventory | 以 source URL／version 去重並 consolidate。 |
| 同一 Hero asset 到處貼 | 只有裁切沒有 adaptation | 建 derivative purpose、CTA 與 Channel framing。 |
| 無法準時完成 | 忽略 review bottleneck | 倒排 approvals、localization 與 capacity。 |
